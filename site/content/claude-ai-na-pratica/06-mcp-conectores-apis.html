Sem esta peça, o Claude apenas conversa. Com ela, o Claude age. A peça se chama MCP — e este artigo explica, sem jargão, as cinco peças que estão por trás de praticamente toda automação séria que você vai ver por aí: MCP, tool use, Claude Desktop, API e webhook.

MCP: o USB-C das inteligências artificiais

MCP significa Model Context Protocol, Protocolo de Contexto de Modelo. E a melhor definição que eu conheço é essa: o MCP é o USB-C das inteligências artificiais.

Pense no que o USB-C resolveu. Antes, cada aparelho tinha o seu cabo, o seu conector, o seu adaptador. Depois, um padrão só, que serve para tudo. O MCP faz isso com as ferramentas de software: é um protocolo aberto que conecta a inteligência artificial a ferramentas, sistemas e dados externos, de forma padronizada.

O que ele permite, na prática? Conectar o Claude ao Google Drive, ao Slack, ao GitHub, a bancos de dados, a APIs, a CRMs e a sistemas internos da sua empresa.

Um exemplo do meu negócio, para sair da abstração: eu ligo o Claude ao sistema da Villela Stay e digo: “verifique as reservas de amanhã e gere as mensagens automáticas no WhatsApp”. Repare que ele não está me sugerindo o que fazer. Ele está consultando o sistema de verdade e produzindo o resultado.

Dois termos para alinhar o vocabulário:

  • CRM é como uma central de informações dos seus clientes. Em vez de dado espalhado no WhatsApp, no caderno, na planilha, no e-mail e na sua memória, o CRM organiza tudo num lugar só.
  • API significa interface de programação de aplicações. De forma simples: é uma ponte que permite que um sistema converse com outro. (Voltamos a ela daqui a pouco.)

Ideia-chave: sem MCP, o Claude conversa. Com MCP, ele conversa, executa ações e acessa sistemas.

Tool use: quando a IA usa ferramentas

Tool use é a capacidade da inteligência artificial de chamar ferramentas externas. Deixa eu mostrar como isso muda uma resposta.

Alguém pergunta se tem quarto disponível.

  • Sem tool use, o Claude responde com base no que ele sabe do texto da conversa. Ou seja: chuta educadamente.
  • Com tool use, ele consulta o calendário do sistema, verifica o CRM, busca os preços — e só então responde.

A pergunta é a mesma. A natureza da resposta é completamente diferente: uma é opinião, a outra é fato. E o MCP é o padrão que organiza essas ferramentas para a inteligência artificial usar com segurança — porque uma IA capaz de agir dentro dos seus sistemas é poderosa e é perigosa na mesma medida. O que separa uma coisa da outra é o controle de quais ferramentas ela pode usar, e até onde.

Atenção — o detalhe honesto que derruba muito mito da internet: o Claude não executa nada sozinho. Ele pede. Quem roda é o seu sistema, o seu código, a sua infraestrutura. Ele diz “quero consultar o calendário”, o seu sistema consulta e devolve o resultado, e aí ele continua o raciocínio. Parece detalhe técnico, mas é o que explica por que um agente que roda no seu computador precisa da máquina ligada — e por que a responsabilidade continua sendo sua.

Claude Desktop: navegador ou aplicativo?

Muita gente usa o Claude só pelo navegador e nunca descobre que existe uma versão instalável, que abre portas que a versão do navegador não abre.

O Claude Desktop é o Claude instalado no seu computador, para Windows ou Mac. Serve para o que você já faz — conversar, criar texto, analisar arquivo. Mas a grande vantagem é outra: ele conecta o Claude às ferramentas locais da sua máquina — arquivos, pastas, banco de dados local, ferramentas de programação, controle de versão, editores de código, automações locais e servidores MCP.

Dois exemplos concretos:

  • “Leia os arquivos desta pasta e organize em Markdown.” Ele acessa a pasta, lê os arquivos permitidos e organiza.
  • “Veja esse projeto e explique o que foi alterado.” Ele usa as ferramentas locais para analisar.

Meu conselho é direto: para uso comum, o navegador resolve muita coisa — não instale nada por instalar. Mas, no momento em que você quiser que a inteligência artificial toque nos seus arquivos, nas suas automações e nos seus sistemas, o aplicativo de desktop passa a ser o caminho.

Consequência prática importante, que volta nos módulos 11 e 13: rotina agendada que roda na sua máquina exige o computador ligado e o aplicativo aberto no horário.

O que é uma API, para quem não é programador

Vou explicar API do jeito que eu gostaria que tivessem me explicado.

A API funciona como um garçom entre softwares. Você faz um pedido. O garçom leva até a cozinha. A cozinha prepara. E o garçom traz de volta a resposta. Você não precisa entrar na cozinha, não precisa saber onde fica a panela, não precisa conhecer o chef. Só precisa saber fazer o pedido do jeito certo.

Com API, o Claude busca informação, envia dado, automatiza processo e integra plataforma. É por isso que existe uma frase forte no livro: as APIs transformam o Claude em infraestrutura empresarial.

No meu caso, uma API pode conectar o site de reservas, o WhatsApp, o Google Calendar, o Booking, o Airbnb e o sistema financeiro. E aí a regra passa a ser: “quando entrar uma reserva no Booking, envie mensagem no WhatsApp e registre no calendário”. Isso deixou de ser tarefa de alguém. Virou comportamento do sistema.

Quatro palavras que você vai ouvir sempre:

Palavra O que é Na metáfora do garçom
Endpoint O endereço da API O balcão onde você faz o pedido
Request O que você envia O pedido
Response O que volta O prato
JSON A linguagem universal das integrações O idioma em que pedido e resposta são escritos

Endereço, pedido, resposta, idioma. Se você entendeu essas quatro palavras, você entendeu API — e vai conseguir conversar com qualquer desenvolvedor sem se sentir perdido.

A estrutura moderna de uma automação

Agora a estrutura que está por trás de praticamente toda automação séria hoje. São seis etapas em sequência — e, uma vez que você enxerga isso, não desenxerga mais:

  1. Cliente. Alguém faz alguma coisa: manda uma mensagem, preenche um formulário, faz uma reserva.
  2. Canal. WhatsApp, ou qualquer canal por onde essa ação chega.
  3. Webhook. O aviso em tempo real. O canal grita: “aconteceu algo aqui”.
  4. Make ou n8n. As plataformas de automação. Recebem o aviso e orquestram o que vem depois.
  5. API do Claude. Aqui entra a inteligência. A automação envia a situação, e o Claude interpreta, raciocina e decide o que responder.
  6. Banco de dados. O registro fica guardado. E, no fim, a resposta automática volta para o cliente.

Repare numa divisão de papéis que é o coração de tudo:

O Claude é a inteligência. Ele interpreta, raciocina, responde. A plataforma de automação é o executor. Ela conecta sistemas, move dado, dispara ação.

Confundir esses dois papéis é o erro mais comum de quem começa: gente que tenta fazer a plataforma de automação pensar, e gente que tenta fazer a inteligência artificial executar sozinha. Cada um no seu quadrado, o sistema funciona muito bem.
